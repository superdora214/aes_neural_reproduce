# AES复现学习记录（2026-10-24）

## 目标与已完成范围

围绕张柳等人的两轮AES双字节区分器，先完成独立PyTorch实现和正式训练，再用独立数据评价，最后补充三轮AES的16位子密钥恢复。当前成果属于指标复现，不是作者架构的严格等价移植，也不是新的混合差分设计。

## 实验过程

1. AES实现通过标准向量、1–10轮两种末轮设定的随机标量对照和输入不变性检查。
2. 小测试以20万训练、2万验证、2个epoch确认流程；该权重与最终模型不同。
3. 正式训练使用1000万训练、100万验证、20epoch、batch1000，完成后再用100万独立测试。
4. 参数、种子、环境、源文件哈希、历史指标和全部20轮权重在完整本机归档中保留。
5. 下载时曾把小测试权重与正式测试指标混在一起，通过SHA256发现并纠正。公开最佳权重与正式测试记录匹配。
6. 本机又生成100万新样本，并对1000个随机密钥做1/2/3对明文的配对攻击评估。

正式模型最佳epoch是1，云端测试Acc=0.998053968，本机新样本Acc=0.998057，均接近论文表5的0.9980。它们是不同样本上的结果，不能混写为一次测试。

## 为什么准确率约99.8%

两轮AES在所选字节上存在同源差分关系。记两侧密文第0、1字节差分为d0、d1，正例满足 `d1!=0` 且 `d0=xtime(d1)`。xtime是AES有限域中乘02，不是普通整数乘法。

全部65536个双字节差分中有255个满足该关系；随机负例均匀时，显式规则误报率是255/65536，类别平衡时准确率约0.9980545。在本机新100万样本上，该规则准确率0.998069，网络0.998057，只有12个分类不同。

这支持“模型行为与已知差分关系高度一致”的解释，不证明网络内部只有这一特征，也没有显示网络优于显式规则。这个对照是训练后的探索性分析，不能包装为预先设计的新贡献。

## 第14轮异常

训练日志中第14轮验证Acc降至约0.745333，第15轮恢复。保留的第14轮权重在新100万数据上Acc=0.744705，TPR约0.491384；第15轮Acc=0.998057。异常存在于该轮权重的推理行为中，不只是日志舍入。

尚未确定具体根因，不能直接断言由BatchNorm或某一实现错误引起。当前最佳模型为第1轮，没有被该异常轮替换。只保存最后一轮、不保存选择依据，会妨碍判断这类问题。

## 作者源码核对后的修正

作者公开源码采用TensorFlow/Keras；双字节输入为长度16、通道2，即通道优先形式`[N,2,16]`。当前实现采用`[N,4,8]`，卷积融合和相邻关系不同，因此先前“结构相同”的表述需要纠正。

作者使用Conv/Dense kernel的L2 regularizer，当前实现使用Adam全参数weight decay。作者含regularizer的Keras模型以val_loss选择模型，当前实现以纯验证MSE选择。两者都填写1e-5或使用相近准确率，不足以证明训练完全等价。

论文batch为1000；当前公开作者入口又会把bs乘以5个GPU副本数。我们记录实际单卡batch1000，不把当前公开入口无修改运行的行为等同于论文全部实验的精确设置。

参考 [作者固定提交](https://github.com/CryptAnalystDesigner/differential-neural-cryptanalysis-on-aes/tree/6556c7b53f25eca35785c738c9834d2b09ff39a0)。当前训练代码的核心计算保持原实验版本；注释及说明已澄清差异。原训练源代码快照和哈希保留在实验目录。

## 区分器与攻击成功率不能混同

1000个配对攻击实例中，1/2/3对明文只有4/531/1000次正确且唯一第一。高分类准确率不代表一次候选搜索中只有正确密钥高分；必须实测错钥响应和候选排名。

当前只恢复K3两个字节。尚未完成八组字节拼接、完整主密钥恢复、原论文全部表格或更高轮攻击。一个训练种子也不能代表多次重新训练的稳定性。

## 阶段结论

可复查的链条是：加密正确性 → 标签及编码 → 训练 → 验证选择 → 最终测试 → 权重绑定 → 部分密钥恢复。它可以作为学习材料和后续实验基线；严格原版复现仍需先对齐输入及训练口径，再另做训练，不把当前权重冒充原版模型。
