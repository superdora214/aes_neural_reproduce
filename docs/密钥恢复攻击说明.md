# 三轮 AES 的16位子密钥恢复

## 攻击目标与数据

每个实验实例使用一个随机128位主密钥，构造指定差分的明文对，加密三轮。第三轮省略MixColumns。任务只恢复第三轮轮密钥K3的第0、13字节，共16位。

AES为列优先编号，ShiftRows使两轮状态的字节0、1在第三轮移动到位置0、13。因此不能直接猜K3的0、1字节。脚本启动时对全部16个字节检查剥轮映射。

## 候选评分

对65536个候选分别执行末轮密钥异或、逆行移位和逆S盒的相关字节运算，把所得两轮状态的字节0、1编码后送入模型。候选评分函数只接收密文与模型，不接收密钥或真实中间状态。

多对数据的评分是各模型输出对数几率之和：`sum(log(p/(1-p)))`。为避免数值无穷，p截断到 `[1e-6,1-1e-6]`。候选排序后才查询模拟实验真值，计算命中和排名。

## 如何运行

```bash
python key_recovery.py --checkpoint checkpoints/net_r2b01.pt --trials 100 --pairs 3 --seed 20261028 --device cuda
```

默认在runs中新建结果目录，每个实例结束就写results.json。无GPU可选cpu，但枚举推理较慢。指定outdir时必须使用尚不存在的目录。

## 指标定义

- `top1_correct`：argmax候选与真值相同；存在并列时可能受候选顺序影响。
- `rank_best`、`rank_worst`：把同分候选分别作有利、不利排序时的真值排名，从1开始。
- `unique_rank1`：真值分数严格高于其他所有候选，比单纯argmax命中更严格。

## 本次对照

固定一份训练模型，随机种子20261030，预生成1000个随机密钥及每个实例的3对明文；1/2/3对设置分别取前1/2/3对。这样控制了密钥和数据变化。

| 对数 | 正确且唯一第一 | 真值最差排名最大值 |
|---:|---:|---:|
| 1 | 4/1000 | 499 |
| 2 | 531/1000 | 4 |
| 3 | 1000/1000 | 1 |

原始逐次记录见 [attack_trials.csv](experiments/20261024/attack_trials.csv)，区间见 [attack_summary.json](experiments/20261024/attack_summary.json)。1000次全部成功不保证理论成功率恒为100%。

本机GPU为RTX5060 Laptop。三对数据全候选评分的中位时间约83.8ms，排除模型加载、加密数据准备和程序启动；这不是完整攻击流程的总用时，也不是原论文的完整时间复杂度。

## 与论文完整攻击的边界

本项目没有训练其余七组双字节区分器并拼接全部K3，也没有逆编排获得128位主密钥。原作者代码包含阈值筛选、候选保留和重试逻辑，本项目用固定数据下的完整排名验证核心机制，不声称逐行复刻这些策略。
